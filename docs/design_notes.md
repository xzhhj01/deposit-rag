# 설계 노트 — 겪은 문제와 해결

RAG 파이프라인 설계문서의 "컬렉션 · 청킹 · 프롬프트를 그렇게 선택한 이유와 겪은 문제, 해결 과정"에 옮길 기록.

---

## 1단계 · 메타 색인 (F2001 ~ F2002)

### 결과
- 금감원 금융상품한눈에 API에서 예금 · 적금 771건 수집 (은행 100 · 저축은행 671), 공시월 2026-10
- `product_meta` 컬렉션에 상품 1개 = 청크 1개, id = `유형:금융사코드:상품코드`
- 두 번 색인해도 771건 유지 (upsert)

### 문제 1 — 상품 전체 텍스트로는 우대조건 검색이 안 된다
| 질문 | 기대 상품 | 상품 전체 텍스트 1청크 | 우대조건 줄 단위 |
|---|---|---|---|
| 대중교통 이용하면 금리 더 주는 상품 | KB맑은하늘적금 | 390위 / 771 | **6위** (1위 NH내가Green초록세상적금도 대중교통 조건 보유 — 정답) |
| 공과금 자동이체하면 우대해주는 적금 | 우리SUPER주거래적금 | 421위 / 771 | **2위** |
| 대중교통 | KB맑은하늘적금 | — | **2위** |

- 원인: 모든 상품 텍스트가 같은 서식(상품명/금리표/만기 후 이자율…)을 공유해 임베딩이 서식에 끌려간다.
  우대조건 한 줄("대중교통 미션")은 긴 텍스트 안의 작은 부분이라 벡터에 거의 반영되지 않는다.
- 시도: 서식을 빼고 요약문만 임베딩 → 오히려 나빠진 경우도 있음 (390위 → 546위). 길이 문제가 아니었다.
- 해결 방향: 우대조건을 **조건 한 줄 = 청크 하나**로 쪼개 따로 색인하고, 상품 점수 = 가장 가까운 조건 줄의 점수.
  조건 탐색(F2011)에서 적용한다. `product_meta`는 상품 1개 = 1청크로 유지한다 (질의응답의 "항상 포함하는 메타 근거"로 쓰고, 검증 4.1의 건수 일치를 지키기 위해).

### 문제 2 — 숫자 조건과 유형은 임베딩이 구분하지 못한다
- "금리 3% 넘는 적금" → 상위 5개 중 4개가 **정기예금**. "적금"이라는 단어도, "3% 넘는"이라는 크기 비교도 보장되지 않는다.
- 해결 방향: 숫자 · 범주 조건은 메타데이터 필터(`kind`, `group`, `best_max_rate`)로 처리하고, 의미 검색은 우대조건처럼 문장으로 된 조건에만 쓴다.
  자연어 조건 → LLM이 필터 값과 의미 조건으로 나눠 추출 → 필터 + 의미 검색 → LLM 최종 선별 (F2011).

## 3단계 · 외부 문서 색인 (F2005)

### 결정 — 문서 범위(scope) 3단계
영화는 "영화마다 관련 문서"가 있지만, 예·적금 771개는 상품마다 위키 문서가 따로 없다. 대부분은 모든 상품이 함께 쓰는 개념 문서다.

| scope | 예 | 청크 id | 검색 범위 필터 |
|---|---|---|---|
| common | 예금보험, 복리, 원천징수 | `common:wiki-ID:순번` | 모든 상품 |
| company | KB국민은행 문서 | `company:국민은행:wiki-ID:순번` | 그 금융사 상품 |
| product | 질문할 때 수집한 문서 (5단계) | `상품ID:wiki-ID:순번` | 그 상품만 |

같은 위키 문서가 공통으로 한 번, 특정 상품의 근거로 한 번 들어가도 scope_key 가 달라 서로 덮어쓰지 않는다.

### 결과
- 공통 18건 · 금융사 29건(은행 16/18, 저축은행 13/79) → 1000자/200자 기준 135청크
- 청크 500자/100자로 바꾸면 268청크, 1000자로 되돌리면 다시 135청크 (검증 4.2)
- 다시 색인할 때 같은 문서의 이전 청크를 먼저 지운다. 지우지 않으면 500자 때 만든 #135~#267 청크가 남아 섞인다.
- 받은 위키 본문은 cache/wiki_pages/ 에 저장 → 두 번째 실행부터 위키 호출 0회 (3분 15초 → 1분 12초, 남은 시간은 임베딩)

### 문제 3 — 위키 검색어 · 넘겨주기가 엉뚱한 문서로 데려간다
- 검색: "단리" → 청풍면(제천시), "중도해지" → 중도우파, "파킹통장" → 맥쿼티
- 정확한 제목으로 받아도: "단리" → 넘겨주기 → "청풍면 (제천시)" (마을 이름 단리)
- 해결: 공통 문서는 제목을 눈으로 확인해 고정하고, 받은 문서 제목이 요청한 제목을 포함하지 않으면 버린다.
  질문할 때의 자동 수집(5단계)에서는 후보 선별 프롬프트(프롬프트 2)가 이 역할을 맡는다.

### 문제 4 — 위키에 한국 예·적금 실무 정보가 얇다
- "이자에 세금이 얼마나 붙어?" → 소득세 · 원천징수 문서가 상위 4개에 없다. 위키에 "이자소득세 15.4%" 같은 실무 수치가 거의 없다.
- "복리" 문서는 134자, "만기"는 93자뿐이다.
- 해결 방향: 종류가 다른 출처(한국은행 경제금융용어 700선 PDF 등)를 함께 색인 → 심화 F2016.

### 문제 5 — "이 은행"처럼 대상을 말하지 않는 질문
- "이 은행은 언제 생겼어?"(카카오뱅크 범위) → 상위 3개가 모두 네오뱅크 공통 문서. 질문에 '카카오뱅크'가 없어서다.
- 해결 방향: 검색할 때 질문 앞에 선택한 상품명 · 금융사를 붙인다 (4단계 retrieve 노드).
